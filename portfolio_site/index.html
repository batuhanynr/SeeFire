02 — Concept

A Raspberry Pi on wheels that patrols a known floor plan and fuses three senses into one verdict: fire, or clear.

  • visioncamera watches for flame & smoke
  • smokeMQ-2 gas sensor reads the air
  • heatMLX90614 measures surface temperature

03 — Hardware

Built on a Raspberry Pi 4. No Arduino — every pin driven straight off the GPIO header.

DRIVE

Locomotion

Chassis
4WD double-deck acrylic, 4 DC gear motors (FL·FR·RL·RR)
Drivers
2× L298N — front + rear, signals wired in parallel
Steering
Tank turn · differential, PWM on GPIO12 / GPIO13 @ 1 kHz
Odometry
2× wheel encoders (GPIO6 / GPIO7) · 20 ticks/cm
SENSE

Perception

Range
3× HC-SR04 sonar — left · front · right, ECHO via 1k/2k divider (~3.18 V)
Smoke
MQ-2 gas → MCP3008 ADC CH0 (SPI) · 60 s warm-up
Heat
MLX90614 IR thermometer · I²C 0x5A · trip at 60 °C
Vision
Logitech C270 USB camera · 640×480 capture
POWER

Power & alarm

Battery
LiPo 2S 7.4 V · low 6.8 V / critical 6.4 V (divider-sensed)
Logic
LM2596 buck → 5.0 V to the Pi, isolated from motor rail
Alarm
LED on GPIO26 (330 Ω) + active buzzer on GPIO19
Compute
Raspberry Pi 4 · BCM GPIO · I²C + SPI buses
CODE

Software

Stack
Python · 7 modules (M1–M7), parallel ownership
Navigation
Waypoint sector traversal · start-position verify · median-filtered sonar
Decision
FSM: INIT → NAVIGATE → VERIFY → ALARM → STOP · weighted sensor fusion
Logging
SQLite (WAL) events + JPEG snapshots · runs in mock mode off-robot
M1 Chassis M2 Motors M3 Sensors M4 Vision M5 Navigation M6 Decision M7 Logging

04 — Decision engine

One loop, five states. Sensors fuse into a single score; the score moves the machine.

fusion = 0.5·vision + 0.3·smoke + 0.2·heat — cross the alarm threshold and the robot stops to verify before it commits to the alarm.
